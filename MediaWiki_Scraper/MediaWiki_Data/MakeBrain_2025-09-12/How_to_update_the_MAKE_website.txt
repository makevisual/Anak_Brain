== Procedure ==

=== ''Before making contents...'' ===
* Set up a project folder by copying the following folder
 U:\MAKE_SITE\MAKE SITE 10\_projects\[Template]
* Rename the copied [Template] as the project, following the name convention as Client-Project title
 ex) Easton[Client]-B5Pro[Project title]
* Collect source materials and save them in [Client-Project]/Src/img OR vid, depending on the format of the source
* Src vs. Content
** Src refers original, raw files; Content refer compressed/trimmed versions of Src files. You place Contents on your Semplice project.
* You DO NOT use Src materials as they are since they are usually huge in size, which make the overall page loading VERY SLOW.
* BTS edit is often made alongside with a project breakdown webpage by artists. Communication with others, especially those who worked on the project, is very important to gather BTS assets.
* BTS contents may not be available right away since it takes times for the artists to extract the assets/elements for the breakdown. You may start with layouts and stills while waiting for the assets being gathered.
* Ask the artists that worked on the project if you don't know where to find them. Make a subtask(s) under the project breakdown Wrike task featuring a list of items/assets you need. Assign it to the project lead/artists, so he/she can forward it to the right person.

* Crop images if necessary: all images are in 16:9 ratio by default. However if you want to place the images in somewhat more interesting ways, you can crop images as doing some math around it. Keep it in mind that the website is 12 columns wide

* Make a thumbnail video: 5~6 sec, 24 fps, 1280x720 px

* Export them through Media Encoder using the custom compression setting for the web:  
 U:\MAKE_SITE\MAKE SITE 10\Assets\MediaEncoder_setting

** Export and save the videos

==== Label the videos: Naming convention ====
* Edits:  [TAG]__SPOT_[original file name OR recognizable file name]
* BTS: [TAG]__BTS_[recognizable file name]
* Thumbnails: [TAG]__THUMB_[client-project]

* MAKE Originals
** Edits: ORIGN_[TAG]__SPOT_[original file name OR recognizable file name]
** BTS: ORIGN_[TAG]__BTS_[recognizable file name]
* Thumbnails: ORIG_[TAG]__THUMB_[project_title]
* Coming up with recognizable tag is important since you cannot make too many separate folders in Amazon Cloud Front -- it only makes URLs on the files way too long. This means you will have to actively use Search function.
* Once you complete the compressions and labeling, move MP4s to the related folders here. Collect the compressed videos, including edits, BTS, and thumbnails and save them here for more efficient cataloguing.

* '''What are the 'Bookmarks' by the way?'''
** Bookmarks are empty projects simply to indicate what are the project breakdown or pitches or whatsoever. Semplice doesn't have intuitive organization system for projects, so we had to invent our way to sort things out.
** Bookmarks in RED vs. YELLOW
*** Yellow means the bookmark itself IS a template of following subjects like pitch, projects (work), and project (archive). You may duplicate this bookmark to start a new project.
*** Red means it's completely empty and it is created purely to sort out projects. Do not use it.
*** Once a new project(s) are complete, place them right after the relative bookmark.

==== Placing contents ====
* When it comes to the stage to handle stylings, please remember the following elements
* images, texts, and videos: contents we want to present
* Size of images and videos can be modified by controlling column width
* When you make a new text using a module besides ones in MAKE custom blocks, use FLUID TEXT module
* Fluid text allows you to make your text fluid without accessing each viewport
* Column: MAKE website is based on 12 column width, Fluid format by default. With columns, you can control positions of your elements. Simply click and drag the handles on each end of the box to modify.[[File:Column.png|none|thumb|916x916px|Column]]
* Section: a bigger container that includes column/spacers, images, texts, and other visual elements. Sectioning elements by subject is very important to move around big chunks of contents together.

* Add Image/Self Hosted Video and Text modules are the most frequently used ones[[File:Modules.png|none|frame|[[File:More useful modules.png|frameless|956x956px]]Basic Modules]]

==== Offsetting and Stack Order ====

* By using Offset and Stack Order in Styling tab, contents can be 'out of the box'! It can make the overall layout more dynamic and interesting.
* Stack Order: Stack order indicates the priority of a content. In other words, it's the order of "layers" (=contents), and the larger the number is, the higher it is in the stack. Between 10 to 15 is usually enough to put the material on the top of the stac[[File:Stack Order.png|none|thumb|613x613px|Stack Order: put larger number if you want to have it on the top of other contents.]]

=== ''Responsive Design'' ===
[[File:Responsive Design.png|none|thumb|1000x1000px|Responsive Design mode]]

* Once all the contents are laid out, make sure the page looks good in various screen modes.
* This process requires going back and forth between preview and editing mode several times. Preview the responsive design by resizing the web browser window.
* Sometimes it's necessary to duplicate a section(s) and edit them to be shown only in mobile versions (usually Tablet Portrait and Mobile) for better readability and flow of info.[[File:Section duplicate.png|none|thumb|1280x1280px|Duplicating sections for different screen mode.]]
* Column mode - Single vs. Multi
** Column mode is only available Tablet Portrait and Mobile responsive modes. You can find this setting in Section menu.
** Some sections may have lots of imageries or contents and it can become really long in mobile mode. Depending on the amount of text and visual contents, you can set the column mode to multi.[[File:Single or multi.png|none|thumb|1184x1184px|Single vs. Multi in Column mode (only in Mobile and Tablet Portrait mode)]]

=== ''Draft to Published'' ===
* Draft: it's draft. Literally. It is not accessible in public
* Published: the project becomes live, accessible in public[[File:Draft and Publish.png|none|frame|Draft and Publish]]
* Even if it's work in progress stage, sometimes you need to publish the project for a writer's reference. When you do so, make sure to publish the project '''with password'''﻿.﻿[[File:Password.png|none|thumb|518x518px|Type in the password before clicking Publish Changes]]
** '''''For the web pitches, you must set up the password since they often have the info of unannounced products or projects. Consider all the pitch decks are confidential.''''' 
* On Projects or Pages, pages/projects can be toggled between Draft and Published by clicking the text itself (red in the image)'[[File:Toggle between Draft and Published.png|none|frame|Toggle between Draft and Published]]
* ﻿ Make sure you save the project before publishing or previewing (eye icon)
* Everything looks good and awesome?
** Save the project, then publish, and make sure everything behaves correctly.
